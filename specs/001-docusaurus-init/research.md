## Research Tasks

### 1. Docusaurus Version & Initialization

**Decision**: Use Docusaurus 3.x with `@docusaurus/preset-classic`

**Rationale**:
- Docusaurus 3.x is the current stable version (as of 2026)
- `preset-classic` includes all required plugins: docs, blog (disabled), theme, sitemap
- Official recommendation from Docusaurus documentation
- Node.js 18+ LTS required

**Alternatives Considered**:
- Docusaurus 2.x: Outdated, lacks latest features
- Custom plugin setup: Unnecessary complexity for standard documentation site

**Initialization Command**:
```bash
npx create-docusaurus@latest physical-ai-book classic
```

### 2. GitHub Actions Deployment Workflow

**Decision**: Use modern `actions/deploy-pages@v4` workflow

**Rationale**:
- Official Docusaurus recommended approach (2024+)
- Uses GitHub's native Pages deployment
- No need for `gh-pages` branch or PAT tokens
- Permissions managed via workflow YAML

**Alternatives Considered**:
- `peaceiris/actions-gh-pages@v3`: Older approach, requires gh-pages branch
- Manual `npm run deploy`: Not CI/CD, requires developer action

**Workflow Structure**:
```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: build

  deploy:
    needs: build
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/deploy-pages@v4
```

### 3. Sidebar Configuration Pattern

**Decision**: Use autogenerated sidebar with explicit category structure

**Rationale**:
- Docusaurus supports `type: 'autogenerated'` for automatic file discovery
- Combined with `_category_.json` files in each directory for labels/ordering
- Reduces manual maintenance as content grows
- Matches spec's directory structure requirements

**Alternatives Considered**:
- Fully manual sidebar: High maintenance burden
- Pure autogenerated: Less control over labels and ordering

**Pattern**:
```javascript
// sidebars.js
export default {
  tutorialSidebar: [
    'intro',
    {
      type: 'category',
      label: 'Module 1: The Robotic Nervous System (ROS 2)',
      items: [{ type: 'autogenerated', dirName: 'module-1-ros2' }],
    },
    // ... other modules
  ],
};
```

### 4. Custom CSS for RTL Support

**Decision**: Add CSS custom properties in `src/css/custom.css`

**Rationale**:
- Docusaurus uses Infima CSS framework with `--ifm-*` variables
- RTL variables can be set and overridden per-language
- Foundation for future `[dir="rtl"]` selector styling

**CSS Variables**:
```css
:root {
  --ifm-direction: ltr;
  --ifm-text-align: left;
  --ifm-font-family-rtl: 'Noto Nastaliq Urdu', 'Jameel Noori Nastaleeq', serif;
}

[dir='rtl'] {
  --ifm-direction: rtl;
  --ifm-text-align: right;
}
```

### 5. MDX Component Placeholder Format

**Decision**: Use JSX comment syntax `{/* <ComponentName /> */}`

**Rationale**:
- Valid MDX/JSX syntax that won't break build
- Easy to find-and-replace when implementing actual components
- Clearly indicates where components should be inserted
- Per clarification session decision

**Template**:
```mdx
{/* <Personalize /> */}
{/* <UrduTranslation /> */}

# Page Title

Content here...
```

### 6. Docusaurus Configuration for GitHub Pages

**Decision**: Configure `docusaurus.config.js` with GitHub Pages settings

**Rationale**:
- Required for correct asset paths when deployed to subdirectory
- `baseUrl: '/physical-ai-book/'` ensures relative paths work

**Configuration**:
```javascript
export default {
  title: 'Physical AI & Humanoid Robotics',
  tagline: 'A comprehensive textbook for modern robotics',
  url: 'https://hood.github.io',
  baseUrl: '/physical-ai-book/',
  organizationName: 'hood',
  projectName: 'physical-ai-book',
  trailingSlash: false,
  // ...
};
```
