# Data Model: Docusaurus Project Initialization

**Feature**: 001-docusaurus-init
**Date**: 2026-01-18

## Overview

This feature initializes a static documentation site. The "data model" consists of content entities represented as markdown files and configuration objects. No database or persistent storage is involved.

## Content Entities

### Module

A major section of the textbook covering a unified topic area.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | Yes | Directory name (e.g., `module-1-ros2`) |
| label | string | Yes | Display name in sidebar |
| position | number | Yes | Sort order in sidebar |
| description | string | No | Brief description for index page |
| topics | Topic[] | Yes | Child topic pages |

**Lifecycle**: Created once during initialization. Updated when curriculum changes.

**Instances** (per constitution):
1. `module-1-ros2` - "Module 1: The Robotic Nervous System (ROS 2)"
2. `module-2-simulation` - "Module 2: The Digital Twin (Gazebo & Unity)"
3. `module-3-nvidia-isaac` - "Module 3: The AI-Robot Brain (NVIDIA Isaac)"
4. `module-4-vla` - "Module 4: Vision-Language-Action (VLA)"

---

### Topic Page

An individual learning unit within a module.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | Yes | Filename without extension (e.g., `01-nodes-topics`) |
| title | string | Yes | Page title (frontmatter) |
| sidebar_position | number | Yes | Order within module |
| sidebar_label | string | No | Short label for sidebar |
| description | string | No | SEO description |
| keywords | string[] | No | SEO keywords |
| hasPersonalize | boolean | Yes | Always true (placeholder present) |
| hasUrduTranslation | boolean | Yes | Always true (placeholder present) |

**Frontmatter Template**:
```yaml
---
title: "Topic Title"
sidebar_position: 1
description: "Brief description for SEO"
keywords: [keyword1, keyword2]
---
```

### Hardware Specification

Documentation of required hardware for the course.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | Yes | Page identifier |
| title | string | Yes | Hardware name |
| type | enum | Yes | `workstation` or `edge-kit` |
| specs | HardwareSpecs | Yes | Technical specifications |

**HardwareSpecs (Workstation)**:
```typescript
{
  gpu: "NVIDIA RTX 4070 Ti+ (16GB VRAM)",
  ram: "32GB minimum",
  cuda: "CUDA 12.x",
  os: "Ubuntu 22.04 LTS or Windows 11"
}
```

**HardwareSpecs (Edge Kit)**:
```typescript
{
  device: "Jetson Orin Nano Developer Kit",
  memory: "8GB unified memory",
  storage: "NVMe SSD recommended",
  power: "15W power adapter"
}
```

### Sidebar Category

Docusaurus sidebar category configuration.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| label | string | Yes | Category display name |
| position | number | Yes | Sort order |
| collapsed | boolean | No | Default collapsed state |
| link.type | enum | No | `doc` or `generated-index` |
| link.id | string | No | Doc ID for category landing page |

**File**: `_category_.json` in each directory

### sidebars.js

```typescript

  tutorialSidebar: SidebarItem[];
};

  | string  // doc ID
  | {
      type: 'category';
      label: string;
      items: SidebarItem[];
    }
  | {
      type: 'autogenerated';
      dirName: string;

```

## Relationships

```
Module 1:N Topic Page
  - A module contains multiple topic pages
  - Topic pages are ordered by sidebar_position

Sidebar Category 1:1 Module
  - Each module maps to one sidebar category
  - Category label matches module title

Hardware Section 1:N Hardware Specification
  - Hardware section contains workstation and edge-kit pages
```

## Validation Rules

1. **Module IDs**: Must match pattern `module-[1-4]-[a-z0-9-]+`
2. **Topic IDs**: Must match pattern `[0-9]{2}-[a-z0-9-]+`
3. **Sidebar Position**: Must be unique within parent directory
4. **Frontmatter**: Must include `title` at minimum
5. **MDX Placeholders**: Every content file must include both placeholders

## State Transitions

This feature creates a one-time initial state. No runtime state transitions.

```
[Empty Repo] → [Docusaurus Initialized] → [Content Structure Created] → [Build Passes]
```
